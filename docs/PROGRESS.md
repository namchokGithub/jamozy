## Current Focus

The Review System UI now ships end to end (see [[DEC-019]]): `/review` (`ReviewPage.tsx`) shows due `ReviewItem`s, `ReviewTypingSession.tsx` practices them by typing — reusing the Korean typing engine, virtual keyboard, and the same `lesson-session-store.ts` Zustand store the lesson flow uses, not a new mechanic — and `application/submit-review-session.ts` advances or resets each item's Leitner box (`submit-review-result.ts`, already existing, does the per-item work). `CourseListPage` shows a "N words due for review" badge (unbounded count, [[DEC-019]] point 1) linking to it. This closes README's Learning Flow: Learn → Type → Review → Improve → Unlock now all exist.

A fresh whole-branch review (Opus) found no Critical or Important code issues — the review's main ask (verify the shared store's `generation`-counter guard, added the round before to fix a cross-mount staleness bug in `LessonTypingSession`, was reused correctly in this round's second consumer) checked out under mutation testing. The one Important finding was this documentation-upkeep pass itself, done here. 8 Minor findings deferred, not fixed this round (see below).

**Still open, not forgotten:** [[DEC-015]]'s MVP-only security gap. [[DEC-018]]'s `ReviewItem.id` uniqueness constraint (still documented, not enforced). New from this round's review, all deferred as genuine Minors: the `itemId` Zod schema accepts values that would make Firestore throw rather than resolve to a clean "not found" (`z.string().min(1).regex(/^[^/]+$/)` would tighten it); `CourseListPage`'s loader now reads the learner's whole `reviewItems` subcollection on every home-page visit (a `where('resolved', '==', false)` query would scale better as items accumulate); `submit-review-session.ts` writes sequentially per item rather than in parallel; a mid-session action failure surfaces `RouteError` rather than a friendlier retry (matches the existing lesson-completion behavior, not new); the due-count badge doesn't pluralize ("1 words due"); no explicit test for re-visiting `/review` after a completed session (the risk is low — `ReviewPage`'s summary state is local, so a remount is fresh by construction); a zero-items `ReviewTypingSession` test from the spec didn't make it into the plan (behavior is correct by inspection, just unpinned); and stray non-typing keys (Tab, Backspace, arrow keys) during a review count as a mistake and reset a box, same as the underlying engine already does everywhere else.

`pnpm build`/`lint`/`vitest run` all pass (142 tests).

Next real steps, not blocked on each other: (1) build remaining `features/` UI (settings, a dedicated dashboard/profile page surfacing EXP and level persistently), (2) a proper Lesson Result screen (currently just an inline block), (3) revisit [[DEC-015]]'s security gap before any real launch.

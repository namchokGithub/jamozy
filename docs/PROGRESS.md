## Current Focus

The interactive "Start Lesson" flow is now fully wired end to end: `LessonDetailPage` → `LessonTypingSession` (sequences a lesson's exercises through the Korean typing engine, virtual keyboard) → a React Router action (`LessonDetailPage.action.ts`) → `application/complete-lesson-session.ts` (Progress/EXP/unlock via the existing `complete-lesson`, plus new `ReviewItem` creation via `create-review-items.ts`). See [[DEC-018]] for the three non-obvious decisions from this pass: the 0–1→0–100 accuracy-scale conversion boundary, `ReviewItem.id = LessonExercise.id` for deterministic point lookups, and a Zustand store `generation` counter needed to survive React `StrictMode`'s dev-mode double-invoke of effects.

A fresh whole-branch review (Opus) found one Critical bug, reproduced independently in the browser: on the most ordinary real path (finish a lesson, go back to the course map via the app's own links, start the next lesson — no page reload in between), the next lesson's `LessonTypingSession` could read a previous lesson's stale, already-completed session out of the shared module-level Zustand store the instant it mounted, silently completing it with the wrong lesson's data before the learner typed anything. Fixed via the `generation` counter above; `LessonTypingSession.test.tsx` now renders through `<StrictMode>` (matching `main.tsx`) so this whole class of bug is caught at the unit level going forward. Full repro and fix narrative in `.superpowers/sdd/2026-09-24-lesson-typing-session/progress.md`.

**Still open, not forgotten:** [[DEC-015]]'s MVP-only security gap (any signed-in user can write `courses`/`units`/`lessons`). [[DEC-018]]'s `ReviewItem.id` uniqueness constraint (exercise ids must stay globally unique, not just lesson-local, or review items from different lessons could merge) is documented but not enforced.

`pnpm build`/`lint`/`vitest run` all pass (122 tests).

Next real steps, not blocked on each other: (1) build remaining `features/` UI (review system, settings, a dedicated dashboard/profile page surfacing EXP and level persistently), (2) a proper Lesson Result screen (currently just an inline block), (3) revisit [[DEC-015]]'s security gap before any real launch.
